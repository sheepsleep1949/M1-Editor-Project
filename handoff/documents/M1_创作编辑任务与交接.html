编辑行为已经定下

新增记录生成 ID；修改标题不换 ID。删除节点时提示影响的选择，确认后同次删除相连选择并更新起点，避免留下隐性链接。结局不能配置出口。条件只允许选择已声明变量；空条件表示总允许；多个条件表示 AND。变量删除必须先列出引用，禁止直接损坏所有选项。

草稿可以处于未完成状态：JSON 类型合法即可保存，结构错误交给检查面板展示并阻断发布。服务端不接受运行状态、ownerId、versionId 混进草稿。保存失败保留本地内容并提示失败，只有服务端返回新 revision 才显示保存成功。

当前画布只读，不能把它算成已完成编辑器。两套故事以配置文件交付；从网页创建第二故事仍是后续验收。

接口 接入步骤与交接清单

你要实现的接口

GET  /api/v1/activities
POST /api/v1/activities
GET  /api/v1/activities/{activityId}/draft
PUT  /api/v1/activities/{activityId}/draft
GET  /api/v1/assets

新建传 {title,requestId}，返回 Draft，HTTP 201。保存传 {expectedRevision,story,layout}，HTTP 200 返回 Draft，revision 加一。服务端从登录会话取得 ownerId；读写都核对活动归属。完整示例见 fixtures/api/save-draft.request.json 与 response.json。

保存核心条件：UPDATE Draft
WHERE activityId = 参数 AND revision = expectedRevision
SET story = 请求内容, layout = 请求布局, revision = revision + 1
影响行数为 0 -> 409 REVISION_CONFLICT

你调用他人的接口

调用 M3 的 POST activities/{id}/checks，传当前 revision，按 nodeId/choiceId 定位。调用 M4 的 POST activities/{id}/versions，传 expectedRevision/requestId；发布失败展示服务器原因。任何编辑或保存导致 revision 变化后，旧报告标为过期。素材只读 assetId，不把磁盘路径写进组件。

按这个顺序交接

1 从 M4 接登录、数据库与资源归属约定，先实现读取和保存。2 将两个 fixture 都导入画布，交给 M2/M3 验证格式。3 与 M3 用一个缺失目标错误核对定位。4 与 M4 用双标签页及“检查后修改再发布”验证冲突。5 提供编辑指南给 M5 编写完整演示。

你交出的材料接收方对方必须验证
草稿 API 与保存示例M4本人可读写、他人不可读写，旧 revision 不覆盖
