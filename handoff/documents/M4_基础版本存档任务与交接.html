账号与环境边界

演示账号为 creator@example.test 与 player@example.test，都是虚构本地账号；密码来自首次 seed 的 DEMO_PASSWORD。数据库仅存加盐哈希。seed 不覆盖已有密码，生产环境拒绝执行。AuthSession 只存随机 Cookie 令牌的哈希。

.env 不入版本库，只有 .env.example 可交接。只包含公开配置的 VITE_ 变量才能进前端；数据库位置、密码和令牌不能放进 VITE_。默认服务绑定本机回环地址。当前鉴权属于课程开发骨架，对外部署前还要完成资源权限与运行配置检查。

首版明确锁定 Prisma 6.19.0。不要直接升级 latest；共享事务使用 db.$transaction 和 Prisma.TransactionClient。

数据库与版本存档接口

实体关系必须保持的不变量
User → Activity → Draft一活动一草稿；revision 条件更新；作者 ID 不能由正文指定
Activity → PublishedVersion每个活动 versionNumber 唯一；story/assets 摘要与规则版本固定
User + Version → PlaySession会话只绑定一个版本；initialState 与当前 state 分开
Session → PlayEvent(sessionId,seq)、(sessionId,requestId) 唯一；追加事件
Session + Version → Save保存服务端当前状态；同时核对玩家、版本及 sourceSeq
Session → FeedbacknodeId/eventSeq 必须能对上实际访问；分享授权有效才给作者
User → OperationReceiptkind/scopeId/requestId 唯一；同载荷重试返回原响应
POST /activities/{activityId}/versions
  {expectedRevision,requestId} -> Version
POST /sessions/{sessionId}/saves
  {expectedSeq,requestId,label} -> Save
POST /saves/{saveId}/restores
  {requestId,shareWithCreator} -> 新 Session

以上均有 /api/v1 前缀。版本 GET 与列表、本人 saves 列表也由你实现。保存不接收 state/versionId，直接读取会话。恢复不接收“最新版本”参数，永远用存档原版。创建、发布、保存与恢复都在同事务写业务数据和 OperationReceipt。

发布交接

从 M1 接 expectedRevision，从 M3 接 validateStory。先捕获候选内容并检查，再在最终事务核对 revision，保存同一候选快照和摘要。旧版本没有更新接口；后续按需加数据库约束防误改。素材 ID 不存在或哈希不符时拒绝发布；文件按内容哈希留存，不覆盖旧资源。运行中加载失败可降级纯文字。

权限交接

提供可复用的当前用户、活动归属、会话归属及分享读取检查函数。业务模块必须调用这些函数。所有外键存在不代表有权限；会话与存档版本一致等跨表业务不变量仍要在事务中验证，不能只依赖 Prisma 的类型。

启动步骤与交接验证

在 starter 根目录使用 Node 22.12 或更高的受支持版本和 npm。按 lock 安装，不重新生成依赖版本。以下命令从根目录执行：

npm ci
复制 .env.example 为 .env 并设置 DEMO_PASSWORD
npm run db:generate
npm run db:deploy
npm run db:seed
npm run verify
npm run dev

浏览器打开 http://localhost:5173。前端代理 /api 到 127.0.0.1:3001；WEB_ORIGIN 与浏览器地址须一致。登录后能加载两套只读配置图。npm ci 若提示依赖安装脚本未批准，按 npm 提示仅批准 Prisma 与 esbuild 的必要脚本，再执行 db:generate；不得跳过失败继续写验收成功。

首次数据库创建的已处理问题

本机 Prisma 6 的空库迁移在 SQLite 文件尚不存在时曾失败。db-deploy.ts 先排他创建空文件，再 migrate deploy；已有文件不覆盖。后续统一使用 npm run db:deploy。测试使用独立临时数据库，不能指向团队正在使用的数据。

给队友的最小交接包

提供仓库提交、README、.env.example、lock、schema/migration、鉴权与 withTx 的导入路径、测试命令、错误格式。队友只需要配置环境变量，不应修改源码中的绝对路径。所有本机数据库、node_modules、Cookie、.env 都不放进分发压缩包。

本模块门禁

M2 和 M5 使用两个账号、两个版本、一份旧存档，完成发布、更新草稿、恢复旧版、继续、回放。然后停服务备份，在独立目录恢复并验证。旧版本被覆盖、跨账号访问、错误绑定最新版、只有本机能运行，都阻断验收。

接手后的第一天

按 README 在独立目录跑一次，认领 auth/db/migration，给每个业务模块提供 requireUser 和资源归属工具。随后与 M1 合作完成真实草稿读写。此时可为 M2 提供专用测试版本创建工具，但标明测试用途，不绕过正式发布门禁。

数据库修改规则

其他人提出字段变更与迁移需求，你审核关系和影响，再生成新迁移。已经交接的旧迁移不得修改。避免直接 db push 改共享数据后忘记留下 migration。备份采用停服务复制或 SQLite 在线备份方法，不能随意复制正在写入且存在未合并 WAL 的单个文件。
