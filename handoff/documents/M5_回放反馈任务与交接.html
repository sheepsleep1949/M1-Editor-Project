字段含义与约束
sessionId / versionId同一会话固定版本；DB 事件通过 session 关联版本，API 返回派生的 versionId
seq / requestIdseq 从 1 起连续；每次成功操作一条；requestId 对同次重试去重
choiceId稳定选择 ID；不以显示文案识别操作
before / after / delta操作前后完整状态和实际变化，三者需可相互核对
initialState / source恢复分支以存档状态为初始状态，source 记录原会话序号
eventSeq / nodeId反馈定位执行后的那次访问；0 指初始状态

恢复样例已经固定

原会话执行两步回到 n_start，key=true、clue=true，保存于原 seq=2。新分支从这个状态开始，seq=0；c_enter 为分支事件 1，c_find 为事件 2。它不是从故事最初的无钥匙状态重新执行，也不删除原来的四条记录。

重复访问怎样区分

基准故事的 n_start 出现在初始 seq=0 和返回后的 seq=2。反馈样例明确绑定 seq=2。因此不能仅靠 nodeId 找反馈位置，必须同时保留 sessionId、eventSeq，并由会话确定 versionId。

样例中的事件 ID、账号和时间均为测试值。正式记录来自服务端执行，不能从前端上报任意 before/after 直接落库。

写入 回放接口与交接

appendEvent(tx, event, requestHash, response) -> Promise<void>
GET  /api/v1/sessions/{sessionId}/events
GET  /api/v1/sessions/{sessionId}/replay
POST /api/v1/sessions/{sessionId}/feedback
PATCH /api/v1/sessions/{sessionId}/sharing

appendEvent 接收 M2 的同一事务；保存 seq/requestId 唯一键、before/after/delta 与原响应。遇到写入错误直接抛出，让 M2 回滚，不能仅记录 warning。事件查询按 seq 升序返回并附 finalSeq，首版最多 500 个成功事件，不能静默截断。

回放处理步骤

验证权限与版本 → 取 initialState → 核对第一个 seq=1 → 逐个核对 before → 调用共享引擎 → 比较 after 和 delta → 记录 choicesBefore → 核对事件数、finalSeq、最终状态。缺失、乱序、状态不符分别返回 EVENT_SEQUENCE_GAP、EVENT_SEQUENCE_ORDER、EVENT_STATE_MISMATCH，status=MISMATCH 并给位置。

反馈 body:
{requestId, eventSeq, nodeId, category, text}
category = bug | confusing | suggestion
text 1 至 1000 字符；版本由服务端会话决定

只有玩家本人可提交；先明确分享给创作者。服务端以 eventSeq 找实际状态核对 nodeId；相同 requestId 同内容只写一次，不同内容报冲突。作者查看按 activityId/versionId 过滤且再次核对当前分享授权。玩家撤回授权后，作者页面和统计都不再返回该会话。
